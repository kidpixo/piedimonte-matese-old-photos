# Constraints
Hard rules. Non-negotiable unless an ADR with a `Waiver:` field explicitly overrides one.

## Required Technologies
- Must use: Jekyll (Lanyon-based) for site generation — Reason: existing site and theme
- Must use: Ruby 3.2 (not 3.3) for Jekyll — Reason: Jekyll 3.9.3 incompatible with the Ruby 3.3 Logger API; 3.3 broke all Docker builds (2026-02 lesson)
- Must use: Python 3.11+ with geopandas/shapely for geometry work — Reason: framework serializers (GeoDataFrame `.to_file`) handle geometries; manual JSON construction silently produced empty FeatureCollections (2026-02 lesson)
- Must use: conda env `cotonificio` to run Python (`python <script>.py`) — Reason: reproducible local environment

## Forbidden Technologies
- Never use: npm/bundler for front-end dependencies — Reason: GitHub Pages static hosting; all external libraries via pinned CDN URLs (see `_config.yml` `cdn_libs`)
- Never use: a backend/server-side state — Reason: static hosting; state lives in URL params, localStorage, or client-side only

## Forbidden Patterns
- Hand-editing `_photos/*.md`: the collection is regenerated by the pipeline every build — edits are lost — Reason: one-way pipeline (see ADR-003)
- Creating separate `raw_data/` entries per image variant — Reason: data drift; one research object = one entry with a variants array (see ADR-001)
- Hardcoding CDN URLs, API keys, or paths in layouts/JS — Reason: single source of truth is `_config.yml` (learned 2026-02-25; see `.ai/archive/2026-02-learnings.md`)
- Adding site JavaScript/CSS outside `assets/` — Reason: public/ folder was migrated to assets/ (Phase 5)

## External Boundaries
- `archive/` is private source material: never deployed, excluded from Docker build context (`.dockerignore`)
- Map tiles: OpenStreetMap (free, CORS-friendly); no tile server requiring API keys
- No hardcoded API keys in source; secrets enter via Jekyll config (environment at build time)
